# 部分返金の仕事の役割の割り当て

対象: `job.md`「部分返金を足す仕事」
使えるエージェント: Claude Code ×2（以下 Claude-A / Claude-B）、Codex ×1。

## 立てる役割

| 役割 | 担い手 | 理由（完了条件から要る成果物） |
|---|---|---|
| manager | Claude-A | 完了条件の判定、受け入れ、main への統合が要る |
| researcher | Claude-B | 代行会社の部分返金の回数上限と、同じ番号での再送時の振る舞いが未確認で、二重返金の設計がこれで変わる |
| worker | Codex | 部分返金の実装と test の結果が要る |
| reviewer | Claude-B（researcher の後） | 書き方と保守性の確かめが要る |

## 割り当て

### manager — Claude-A

目的と完了条件を持ち、worker の完了報告を受けて受け入れを決める。受け入れたら main へ統合し、そのあと reviewer に review を頼む。reviewer の指摘は次の変更で直す。

### researcher — Claude-B

代行会社の部分返金 API について、回数の上限と、同じ番号で二度送ったときの振る舞いを、出典と確認日時の付いた事実として返す。設計の推奨はしない。worker はこの事実が出てから二重返金の防ぎ方に着手する。

### worker — Codex

部分返金の API を実装し、既存の全額返金の test と新しい test を通す。セキュリティの観点（他店舗の注文を返金できないこと）も、自分で test を書いて確かめ、確かめた結果を完了報告に書く。完了報告で止まる。

### reviewer — Claude-B（researcher の仕事の後）

worker の変更の書き方、命名、保守性を読んで指摘する。直さない。

## 未検証になる範囲

advisor を立てていないので、二重返金の方式のトレードオフは manager だけが判断する。代行会社への問い合わせはエージェントにはできないので、公開資料で決まらなければ利用者に頼む。
